# Workflow Builder で「AI で整形」ステップを使う (非エンジニア向けガイド)

このドキュメントは **コードを書かない人** が、エンジニアがデプロイしてくれた「AI で整形」カスタムステップを Workflow Builder から呼び出す手順をまとめたものです。

> スクリーンショットは実機検証時に `docs/screenshots/` に追加されます。当面は文字ベースのガイドのみ参照してください。

---

## 前提

- エンジニアが `slack deploy` を済ませており、対象ワークスペースにアプリが追加されている
- 自分のアカウントが該当ワークスペースに参加している
- `slack env add OPENAI_API_KEY ...` が登録されている (鍵が無いと実行時にエラーで止まる)

---

## 全体像

「Slack のメッセージや投稿フォームから受け取ったテキストを **AI でフォーマル整形して、別チャンネルに送信する**」という最小ワークフローを組みます。

```text
[Link Trigger] -> [AI で整形] -> [メッセージを送信]
```

---

## 手順

### Step 1. Workflow Builder を開く

1. Slack の左サイドバー下部の **「その他 (More)」** をクリック
2. **「Automations」** を選択
3. **「Workflow Builder」** タブを開く
4. 右上の **「New Workflow」** をクリック

### Step 2. トリガーを選ぶ

ここでは **「Link」** (リンクトリガー) を選ぶのが最も簡単です。

- 「From a link in Slack」を選択
- ワークフロー名を入力 (例: `テキストをフォーマル整形する`)
- 開始時に受け取る変数として **`text` (string)** を 1 つ追加
  - "Add variable" → name=`text`, type=`Text`

### Step 3. 「AI で整形」ステップを追加する

1. **「+ Add Step」** をクリック
2. ステップ選択モーダルが開いたら **「Custom」** タブ (または検索窓に `AI で整形` と入力)
3. **「AI で整形」** カードをクリック
4. 設定フォームが開く:
   - **整形するテキスト**: トリガーから渡ってきた変数 `text` を選択 (`{{` で挿入)
   - **整形スタイル**: ドロップダウンから `formal` を選択
5. 「Save」をクリック

### Step 4. メッセージ送信ステップを追加する

1. もう一度 **「+ Add Step」** をクリック
2. **「Send a message to a channel」** (Slack 標準ステップ) を選択
3. 設定:
   - **Channel**: 送信先チャンネル (例: `#test`)
   - **Message**: 本文に直前ステップの出力変数 **`formatted_text`** を挿入
4. 「Save」

### Step 5. Publish (公開)

1. 右上の **「Publish」** ボタンを押す
2. 共有用のリンクが発行されるのでコピーしておく

### Step 6. 実行する

- 発行されたリンクを Slack の任意の場所に貼って開くと、`text` 入力モーダルが表示される
- テキストを入れて「Submit」すると、整形済みの本文が指定チャンネルに投稿される

---

## トラブルシューティング

| 現象 | チェックポイント |
| --- | --- |
| 「Custom」タブに「AI で整形」が無い | エンジニアに `slack deploy` 済みか確認 / ブラウザを完全リロード (`Cmd+Shift+R`) |
| 「整形スタイル」がドロップダウンにならない | `enum` が manifest に入っているか (エンジニア確認事項) |
| 実行時に `OPENAI_API_KEY が未設定` | `slack env add OPENAI_API_KEY ...` を実行してもらう |
| 整形結果がチャンネルに出ない | 送信先チャンネルに **アプリが招待されているか** 確認 (`/invite @pattern-k-custom-step`) |

---

## 応用アイデア

- **トリガーを「絵文字リアクションがついたら」に変更** → 任意の投稿に reaction でフォーマル化
- **整形スタイルをトリガー側の選択肢から渡す** → 一つのリンクで複数スタイルに対応
- **整形後を Canvas に書き出す** → 議事録の整形 → Canvas 保存パイプライン
