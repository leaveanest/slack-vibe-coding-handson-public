# Google ドキュメント作成手順 — Codex App で自動化

`docs/event-2026-05-19/google-doc-handout.md` (約 391 行) を Codex App から Chrome を操作させて Google ドキュメント化し、参加者配布用の閲覧可能 URL を取得するための手順書です。

兄弟ファイル `google-forms-codex-procedure.md` と同じ構造で揃えてあります。

---

## 1. 前提条件

| 項目 | 確認内容 |
|---|---|
| Google アカウント | Chrome でリバネスナレッジ系または配布用組織アカウントにログイン済み (Google Workspace でも個人アカウントでも可) |
| Codex App | <https://developers.openai.com/codex/app> を開いて操作可能な状態 |
| 参照ファイル | `docs/event-2026-05-19/google-doc-handout.md` をローカル clone 済 (推奨) または GitHub raw URL から参照可能 |
| ブラウザ | Chrome のタブが空いていること (Codex App が新規タブで操作する) |
| Drive 容量 | マイドライブに新規ファイルを 1 つ作成できる余裕があること |

> 注意: Codex App はローカル環境のブラウザを制御して操作します。Chrome が Codex App のアクセスを許可している必要があります。初回は許可ダイアログが出る場合があります。

### ローカル clone と raw URL の両方に対応

Codex App に元原稿 `google-doc-handout.md` を読み込ませる方法は 2 通り。プロンプトはどちらでも動くように書いています。

- **方法 A (推奨): ローカルパス参照**
  - public リポジトリを clone 済の場合、ローカルパスをそのまま渡す
  - 例: `~/workspace/slack-vibe-coding-handson-public/docs/event-2026-05-19/google-doc-handout.md`
- **方法 B: GitHub raw URL 参照**
  - clone していない場合は raw URL から取得させる
  - 例: `https://raw.githubusercontent.com/leaveanest/slack-vibe-coding-handson-public/main/docs/event-2026-05-19/google-doc-handout.md`

## ステップ 0: Google Drive を開く

1. Chrome で https://drive.google.com/ を開く
2. ログイン済み Google アカウントが配布用の正しいアカウントになっているか右上アイコンで確認する
3. 左上の「マイドライブ」が表示されている画面で待機する

## ステップ 1: 新規 Google ドキュメントを作成する

1. 画面左上の「+ 新規」ボタンをクリックする
2. メニューから「Google ドキュメント」をクリックする (サブメニューが出た場合は「空白のドキュメント」を選ぶ)
3. 新規 Google ドキュメントが別タブで開くまで待つ

## ステップ 2: タイトルを設定する

1. 開いたドキュメントの左上「無題のドキュメント」をクリックする
2. タイトルを以下の文字列に置換する:
   Vibe Coding ハンズオン 参加者配布資料 (2026-05-19)
3. Enter で確定する
4. タブのファイル名が同じタイトルに変わることを確認する

## ステップ 3: 元原稿 google-doc-handout.md を読み込む

1. 上部に指定された「参照する元原稿のパス」を読み込む
   - ローカルパスの場合: ファイルを読み込む
   - raw URL の場合: HTTP GET でテキストを取得する
2. 取得した md テキストを内部バッファに保持する
3. frontmatter (--- で囲まれた最上部のメタデータブロック) は貼り付け対象から除外する

## ステップ 4: md を Google ドキュメント書式に変換しながら本文に貼り付ける

ドキュメント本文 (タイトル直下) にカーソルを置いた状態で、md テキストを上から順に
以下のルールで Google ドキュメントの書式に変換しながら貼り付ける。

変換ルール:

- `# 見出し` → Google Docs の「見出し 1」スタイル
- `## 見出し` → Google Docs の「見出し 2」スタイル
- `### 見出し` → Google Docs の「見出し 3」スタイル
- `#### 見出し` → Google Docs の「見出し 4」スタイル
- `**太字**` → 太字 (Bold)
- `*斜体*` または `_斜体_` → 斜体 (Italic)
- `` `インラインコード` `` → 等幅フォント (Consolas / Roboto Mono) を適用
- 行頭 `- ` / `* ` / `+ ` → 箇条書き (中点リスト)
- 行頭 `1. ` `2. ` 連番 → 番号付きリスト
- ` ``` ` で囲まれたコードブロック → 等幅フォント + 灰色背景 (#F3F4F6 相当) + 枠線
  - 言語指定 (例: ```bash) は無視してよい
- `| ... |` 形式のテーブル → Google ドキュメントの「表」として挿入 (列数は最上行のセル数に合わせる)
- `[テキスト](URL)` → ハイパーリンク (「テキスト」を選択して URL を埋め込む)
- `<https://...>` 単独 URL → そのまま自動リンク
- 行頭 `> ` 引用 → インデント + 文字色グレー (またはブロック引用スタイル)
- `---` 水平線 → Google ドキュメントの水平線 (挿入 → 水平線) を挿入
- 空行 → そのまま空行として保持

貼り付け中は「ステップ4-N (Nセクション処理中)」のようにログを出すと進捗が分かる。
途中で書式変換に失敗したセクションがあれば、ログに「セクション X は素のテキストとして貼り付け」と
出力して次のセクションに進む (止まらない)。

## ステップ 5: §0 当日リンク早見表のプレースホルダーを確認する

1. 貼り付け完了後、ドキュメント先頭の「§0. 当日リンク早見 (運営記入欄)」テーブルまでスクロールする
2. 表の中に「【当日朝、運営が記入】」というプレースホルダーがあることを目視で確認する (2 箇所: Forms URL と Google Meet URL)
3. プレースホルダーは置換しない (運営が手動で当日記入する想定)
4. プレースホルダーが見つからなかった場合は、ログに「プレースホルダー未検出 — 手動確認が必要」と出力する

## ステップ 6: 共有設定を「リンクを知っている全員が閲覧可能」に変更する

1. 右上の「共有」ボタンをクリックする
2. 共有ダイアログが開いたら、下部の「一般的なアクセス」セクションを探す
3. 「制限付き」になっている場合はクリックして「リンクを知っている全員」に変更する
4. ロール選択ドロップダウンを「閲覧者」に設定する (編集者や閲覧 (コメント可) ではない)
5. 「リンクをコピー」ボタンをクリックしてクリップボードに URL をコピーする
6. 「完了」ボタンを押してダイアログを閉じる

## ステップ 7: 共有 URL を出力する

1. クリップボードにコピーした URL を出力欄に表示する
2. 形式: `https://docs.google.com/document/d/XXXXX/edit?usp=sharing`
3. 末尾に作成サマリを以下の形式で出力する:

   - タイトル: Vibe Coding ハンズオン 参加者配布資料 (2026-05-19)
   - 共有設定: リンクを知っている全員が閲覧可能 (閲覧者)
   - 共有 URL: <上記 URL>
   - プレースホルダー残り: §0 の「【当日朝、運営が記入】」を運営が手動で置換すること

---

以上です。全ステップ完了したら最後に「ドキュメント作成完了」と出力してください。
```

## 3. 手動でやる残り作業 (Codex App 実行後)

Codex App が共有 URL を返したら、以下を手動で実施してください。

### チェックリスト

- [ ] **§0 当日リンク早見表の URL 置換**
  1. 取得した共有 URL を Chrome で開く
  2. §0 の「アンケート (Google Forms)」行の `【当日朝、運営が記入】` を Forms 短縮 URL に置換する
  3. §0 の「Google Meet URL」行の `【当日朝、運営が記入】` を当日の Meet URL に置換する
  4. 置換した状態で別タブからもう一度開いて反映を確認する

- [ ] **短縮 URL を作成 (任意)**
  - 参加者配布用に <https://bitly.com/> や社内 URL 短縮ツールで短縮 URL を生成する
  - QR コードが必要な場合は短縮 URL から生成する

- [ ] **書式崩れチェック**
  - §0 のテーブルが表として表示されているか
  - §3 / §4 / §5 のコードブロックが等幅フォント + 灰色背景になっているか
  - §5.2 〜 §5.5 のリンク (Codex App プロンプト内含む) がハイパーリンクとして青字で表示されているか
  - §8 の表が崩れていないか
  - 見出し階層 (H1 / H2 / H3 / H4) が崩れていないか

- [ ] **運営内レビュー**
  - 共有 URL を運営 Slack に投稿
  - 別アカウントで URL を開いて閲覧者として表示できるか確認
  - 1 名以上が通読してタイポ・崩れがないかチェック

- [ ] **Google Meet チャット欄に URL を投稿する準備**
  - Google Meet のチャット欄に貼るメッセージを下書き

## 4. Codex App が詰まった場合のフォールバック

Codex App が以下のケースで止まった場合は、人手で対処してください。

### ケース 1: Chrome 操作が反応しない

**症状**: Codex App からブラウザクリックや入力が発火しない、または進行が止まる。

**対処**:

1. Codex App の設定でブラウザアクセス権限が有効か確認する
2. macOS の「システム設定 → プライバシーとセキュリティ → アクセシビリティ」で Codex App / Chrome に許可が付いているか確認する
3. Chrome を一度終了して再起動し、Codex App から再実行する
4. それでも動かない場合はケース 4 (完全手動) へ

### ケース 2: 書式変換が崩れる

**症状**: 表が壊れる、コードブロックが等幅にならない、見出しレベルがずれる、リストがネストしすぎる。

**対処**: ステップ 4 を「セクションごとに分割実行」に切り替える。

1. md を `##` (H2) 単位で 9 セクションに分割する (§0 〜 §8)
2. 1 セクションずつ Codex App に貼り付け指示を投げる
   - 例: 「以下のテキストを Google ドキュメント書式に変換しながら本文末尾に追記してください: <セクション 1 の md>」
3. 各セクション貼り付け後にプレビューで崩れを確認する
4. テーブルが崩れる場合は、テーブル部分だけ Google ドキュメントの「挿入 → 表」で手動作成して中身を埋める

### ケース 3: GitHub raw URL から md が取得できない

**症状**: Codex App が raw URL に HTTP GET で取得失敗する (CORS / 認証 / ネットワーク)。

**対処**:

1. ローカルに `google-doc-handout.md` を一度保存する
   - `curl -O https://raw.githubusercontent.com/leaveanest/slack-vibe-coding-handson-public/main/docs/event-2026-05-19/google-doc-handout.md`
2. プロンプト冒頭の「参照する元原稿のパス」をローカルフルパスに差し替える
3. Codex App を再実行する

### ケース 4: 共有設定が反映されない

**症状**: ステップ 6 で「リンクを知っている全員」に変更されない、または閲覧者ではなく編集者になってしまう。

**対処**: 人手で共有設定を変更する。

1. Google ドキュメント右上の「共有」ボタンをクリック
2. 共有ダイアログ下部の「一般的なアクセス」を「リンクを知っている全員」に変更
3. ロールを「閲覧者」に設定
4. 「リンクをコピー」をクリックして URL を取得
5. 別アカウント (シークレットウィンドウ等) で URL を開いて閲覧できるか確認
